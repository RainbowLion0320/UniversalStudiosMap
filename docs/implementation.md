# 实现与验证记录

日期：2026-09-21。

## 架构决策

在初期 Leaflet 选型调研后，按用户新的 Low Poly 要求改为 Three.js + Blender 原生模型；没有保留未使用的 Leaflet 依赖。地图与业务数据共享局部地理坐标原点，三维造型独立于步道计算。

- Blender 5.2.0：约 30 个材质网格批次、约 2 MB GLB。源场景保留物体与集合，重建脚本使用固定种子与版本化 OSM 输入。
- 浏览器：原生 JavaScript + Three.js，正交投影，OrbitControls，HTML 可访问项目按钮。
- Vite 插件：开发与预览服务器共用本地数据 API。数据源限固定地址，不暴露任意 URL 代理；刷新有并发合并、60 秒限流和请求超时，写入采用临时文件后 rename。
- 数据：ThemeParks.wiki 44 条项目快照，OSM 路网 578 节点 / 590 边记录。Queue-Times 原始调研数据仍保存在本地，本版 UI 没有混用其排队值。
- 存储：浏览器 localStorage；从存储恢复时只接受已知字段和有界数值，去重项目 ID；无账户和云同步。

## 保留限制

- 模型是艺术化示意；城堡、轨道高度等非测绘复原，装饰物不参与可通行判断。
- 入口仅连接到最近步道节点并用棕色虚线标示；现场围栏、特殊入口和临时封路未完整核验。
- 自动排序优化步行距离，保留第一站；固定演出与排队仍需用户判断，不声称全局最优。
- 演出无可用场次时给出提示，并使用可编辑时长估算；休息集中计入末尾，不含入园/离园。
- 功能依赖支持 WebGL2 的现代浏览器。本地已有数据可不联网规划，但没有离线安装或 Service Worker。
